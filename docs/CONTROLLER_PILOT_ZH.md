# HypoSpace 学习驱动结构探索方案

本方案用于一天内完成个人候选方法的初步实验，再与同组其他方案比较。主任务限定为 HypoSpace 布尔表达式生成，固定一个 LLM，训练一个可在 CPU 上运行的小型决策模型。当前已实现本地流程，并用本地小模型收集 256 次训练调用；尚未训练控制器或启动测试评测，不能声称效果提升。按用户最新要求，先完成 GPU 与 GitHub 连接，再共同确定方案。

## 正式要求与本轮交付

老师文件的 Part 1.2 要求设计新颖 ML 方法提升 HypoSpace 上的 LLM 表现，方法自由；期末项目占总评 30%；最终提交十分钟小组视频和公开 GitHub 仓库；每位成员参加讲解，全组同分，评分为 novelty、importance、quality。文件未强制两个任务域、GPU 微调、特定模型或单独书面报告。

本轮交付是一个可运行的候选方法、原始实验轨迹、五种方法的比较结果和复现代码。视频属于组内筛选后的小组最终成果。本轮结果不足以代表整个基准。

## 方法及拟研究贡献

研究问题：在同一个模型、同一组观测和同样的生成次数下，学习根据探索历史选择下一种生成操作，能否发现更多有效且规范化后不同的答案？

模型输入包括观测的编码、预算进度、已发现答案的根算子分布、近期有效率、新答案发现率和各动作的历史成功率。操作集合为自由生成、根算子 AND、OR、NOT 引导、嵌套结构引导、修复上一条无效答案、局部修改上一条有效答案。修复和修改均由 LLM 输出一个新候选，不由程序自动生成答案。

我们训练两个带 L2 正则的逻辑回归预测头，分别估计 P(有效 | 状态, 动作) 和 P(新增 | 有效, 状态, 动作)，用二者乘积选择动作。训练用 CPU 上的 NumPy Adam 完成；第二个预测头只在有效训练样本上计算损失。训练轨迹通过随机探索动作得到，标签来自确定性校验与官方规范化去重。测试时模型参数固定，生成历史变化使选择随之调整。

潜在贡献是规范化新增奖励、有效性与新增性分离预测、基于历史选择结构生成或修复的组合，并通过消融说明哪些设计有用。学习路由、条件探索和覆盖奖励本身已有研究，不能仅凭方法名主张全球首创。若学习策略未超过相同动作集合的随机或固定策略，应如实判定当前控制器贡献不足。

## 最小可执行实验

固定任务变量 x 和 y，使用上游 extended 运算符设置及深度 2；保持上游规范化规则。按完整观测集合分开训练、验证和测试，不能把同一题的多条轨迹拆进不同集合。由于变量少，不同题共享表达式结构是任务性质；本次只主张对未见观测条件的泛化，不主张未见假设结构或跨域泛化。

默认训练为十六题、每题十六次生成，共 256 次。测试为六题、两次独立运行、五种方法、每题十六次生成，共 960 次。主体合计 1,216 次生成；可再用六道验证题收集 96 次轨迹；同一实验目录设置 1,400 次请求上限。重复编号不代表远程服务必然支持确定性随机种子。

五种方法是原始带历史记忆的生成、固定结构轮换、同动作集合的随机选择、学习控制器、移除控制器历史特征的消融。最后一项保留 LLM 提示中的历史答案和合法动作掩码，仅去掉预测器的历史结果特征。固定结构轮换不是原论文依赖真值分布分配预算的分层方法。

每次候选都经过同一解析、空间约束、观测一致性和规范化检查。新颖性训练标签只使用当时已生成的有效集合。完整参考答案只用于最后算 RR，不进入控制器状态、提示或动作选择。失败输出和修复调用也计入预算；另报告 token、推理耗时、训练调用数和无效类型。

输出包括 VR、NR、RR，8 次和 16 次预算下的覆盖率，逐题配对差异及按题重采样的区间。六道测试题的区间可能很宽，必须保留不确定性。组内其他方案必须使用相同模型、题目、预算和评测规则后才可公平比较；模板已经放入 results 目录。

## 基准代码审计

上游版本固定为 upstream.lock.json 中的提交，下载文件逐一校验 SHA256。当前发现 full 设置深度 2 时，65 条参考表达式的序列化形式中有 31 条被同版校验器拒绝；extended 设置为 34 条中有 1 条，涉及 NOT 与 OR 被识别为 NOR 的处理。这是代码一致性审计，不是 LLM 实验结果，也不等于证明所有相关规范化键绝对不可达。

本轮选 extended 减少该影响，保留全部原始参考键，不删除分母、不修改上游校验器。我们增加解析和空间约束先行的拒绝检查，避免错误解析被误判为有效；这项协议差异对全部方法一致应用并公开记录。绝对分数不直接与论文表格作同条件比较。

## 执行步骤和时间

| 步骤 | 交付与预计经过时间 |
|---|---|
| 方案审核与运行环境核对 | 核对方案、GPU、模型位置和服务，约 30 至 60 分钟；网络与排队时间另计 |
| 小规模试跑 | 先跑两道训练题，共 32 次调用，约 15 至 30 分钟；据此实测速率再外推全程 |
| 收集与训练 | 收集其余训练轨迹并训练两个控制器；模型训练通常很短，主体时间由生成速度决定 |
| 五组对照 | 共 960 次生成；按 32 次试跑的平均耗时估算，不在未知 GPU 条件下承诺固定时长 |
| 分析与整理 | 导出指标、覆盖曲线、失败案例、组内比较表及可复现包，约 1 至 2 小时 |

已有可用推理环境时，目标是在剩余一天内完成这轮筛选。首次下载模型、长时间 GPU 排队或网络不可用会直接影响可行性。若试跑已经接近满覆盖，先调整预算或报告该设置缺乏区分力，不能根据测试集结果反复挑题制造提升。

## 分工与当前状态

Codex 负责配置、数据、训练、运行监控、分析和仓库整理；用户审核方法，并提供可访问的服务器会话。服务器上先申请一张 GPU，模型按实际显存和已有缓存确定，不在拿到配置前购买资源或指定大模型。

本地已有数据准备、九项协议检查、模拟全流程、断点恢复、请求计数和导出代码。本地 Qwen2.5-1.5B 的 256 次真实训练调用已保存；控制器训练及测试对比尚未开始，后续实验等待方案审核。模拟日志使用专门标识和目录，不纳入真实结果，也不能拿模拟权重评测真实模型。
