# DCHG 与结构类别覆盖 LoRA 的比较协议

用户提供的 DCHG 描述是推理阶段根据已有假设指定未观测位置的预测差异。当前个人候选方法为离线训练的 Canonical Coverage LoRA，推理只读取原始观测与规则。两者独立实现，先分别验证，再在共同条件下比较。

## 已确认的官方规则

老师提供的 PMLR 论文及其官方仓库确定了任务域、假设空间、结构规范化和 VR/NR/RR 评价方式。布尔任务按限制的结构规则区分类别，不能直接按完整真值表合并所有逻辑等价表达式。

论文第 3 节讨论固定提示下的采样，说明多数实验预算设为兼容参考集合大小，也允许其他预算。第 5 节说明布尔结构规范化。论文同时比较多个模型和生成策略；这些设置不是课程指定的唯一模型。

官方 README 的配置步骤允许修改模型、温度、生成器参数、抽样题数和预算；示例使用 --n-samples 30 及 --query-multiplier 1.0。固定的上游 Boolean runner 还支持单题固定查询次数或按参考数量倍数分配预算。因此，老师的链接并不能唯一推出截图中的“34 道开发题、三个种子、每题 10 次生成”。不能把我们枚举到的 34 个结构类别当成她的 34 道开发题。

来源：[论文](https://proceedings.mlr.press/v306/chen26bz.html)、[官方配置与运行说明](https://github.com/CTT-Pavilion/_HypoSpace)、仓库锁定提交见 upstream.lock.json。

## 同组结果能支持的范围

截图明确标注开发集筛选，包含 Validity、novelty_rate、Recovery 和行为覆盖，并说明部分方法相对简单修复等对照优势较小或不稳定。把这些文字视为同组提供的开发记录，不据此推断隐藏的模型、题目 ID、完整实现或独立测试结果，也不据此认定自己的方法会胜出。

目前用户补充的是同一官方论文链接，尚未提供个人实验配置。待核对内容为实际基础模型及量化版本、任务生成设置、34 道题的观测或内容 ID、完整提示与代码、采样参数、种子、上游版本、预算计数及指标实现。现阶段不反复猜测这些配置，也不因此暂停个人方法的设计。

## 方法边界

| 维度 | DCHG 的用户描述 | 本方案的主方法 |
|---|---|---|
| 主要机制 | 推理期指定预测差异并生成 | 训练期改变模型概率分布 |
| 已生成答案 | 参与下一轮条件构造 | 不输入主方法 |
| 未观测位置 | 构造预测差异目标 | 不进入生成条件 |
| 参数更新 | 描述未说明 | LoRA 离线更新 |
| 覆盖对象 | 指定预测差异引导的搜索结果 | 官方结构类别 |

本方案不把差异提示、变量置换、行为保持改写或生成修复循环加入核心方法。仅使用固定序列化及外层冗余括号作为训练编码；这一编码不作为推理生成策略或独立创新点。完整历史、修复等可作为基线，不计作本方法贡献。

## 共同测试与开发题重叠

取得题目观测后，以规范化内容生成 ID，比较双方训练、验证、调参和开发筛选题目的并集。共同测试需在该并集之外，并在运行前固定。内部原有二十六道题仅保证对本方案未使用，不能自动称为双方共同未使用。

若同一小题库缺少足够共同未用题，选择并明确标识开发集筛选比较，或在共同运行前另行约定受控题族、重划并重跑。不得把已经用于筛选的题目改名为 test 后宣称独立泛化。跨方法数据划分的调整不回写旧结果。

## 模型和调用预算

双方从同一基础检查点及量化格式出发。本方案使用额外适配器，DCHG 使用原始模型及其生成策略；记录这种参数差异。比较清单至少包括原始模型、均衡 SFT、本方案、DCHG；有可复现实现时再纳入截图提到的简单修复及完整历史基线。

优先输出每题十次预算下的 RR，并报告 VR/NR、token、推理时间。所有修复与失败生成均计入预算。若存在额外 LLM 规划或条件选择调用，分列候选尝试数与总 LLM 调用数，在相同总调用预算下追加比较；不能隐藏辅助调用。确定性校验与条件计算的 CPU 时间另列。

固定基础模型、观测、提示中共同规则、温度、截断及停止条件、校验与规范化、三个运行编号，并记录后端是否真正支持种子。共同设置须预先商定，不能只照抄截图中的一个数值。保持动态条件本身作为 DCHG 的处理因素。

离线训练消耗单独列为一次性成本，推理开销另列；相同推理预算不等于相同总计算成本。不强制两个机制使用完全相同的输入附加条件，否则会取消被比较的方法。

## 分析及结论边界

本方案内部仍以 RR@16 对均衡 SFT 为主比较，另外输出十次前缀。共同协议另以匹配的 RR@10 比较方法，不能直接把不同题目上的两个平均值相减当作方法效应。

在共同题目内先平均三个随机运行，再计算逐题差异和按题 bootstrap 区间。novelty_rate 统一为代码层面的规范化唯一率；它与课程评分中的创新性不同。行为覆盖若保留，需先对齐定义，作为另一个指标报告，不能替代官方结构 Recovery。

若 LoRA 只优于原始模型而不优于均衡 SFT，不能证明覆盖损失的额外贡献。若 DCHG 与 LoRA 互有优势或区间跨零，报告条件和不确定性，按研究价值、成本与完成质量共同筛选，不预设获胜者。本轮不把 DCHG 拼接进 LoRA 的主方案。

## 本方案已完成的个人结果
已完成 26 道个人固定测试题、三个推理种子、每题 16 次生成。下面是同一批原始序列的前十次结果，未额外调用模型，也未重新选择样本。它仍然不等于与同组 DCHG 的共同测试。

| 方法 | VR@10 | NR@10 | RR@10 |
|---|---:|---:|---:|
| 原始模型 | 15.51% | 42.56% | 10.15% |
| 均衡 SFT | 30.51% | 77.31% | 26.07% |
| 结构类别覆盖 LoRA | 32.44% | 73.21% | 27.55% |
| 字符串覆盖消融 | 36.67% | 68.08% | 26.64% |
| 原始模型＋历史 | 11.41% | 30.00% | 6.98% |

主分析 RR@16：原始模型 13.67%、均衡 SFT 36.86%、结构类别覆盖 LoRA 37.76%。覆盖目标相对 SFT 增加 0.89 个百分点，按题 bootstrap 的 95% 区间为 [-1.97, +3.72]，尚不能确认额外优势。组内筛选时应保留这一限制。
